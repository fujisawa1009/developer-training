## 問題解決とPDCA

仕事では毎日さまざまな問題が発生します。**問題を解決する力**と、改善を継続するための**PDCAサイクル**は、すべてのビジネスパーソンに必要なスキルです。

### 問題解決の基本プロセス

問題解決には正しい手順があります。感覚に頼らず、**論理的に考えて解決する**ことが重要です。

```
1. 問題の発見・定義
   └ 「あるべき姿」と「現状」のギャップを明確にする

2. 原因分析
   └ なぜその問題が起きているのかを深掘りする

3. 解決策の立案
   └ 複数の選択肢を考える

4. 実行
   └ 最善の策を選び、計画的に実施する

5. 評価・改善
   └ 結果を検証し、次に活かす
```

### 原因分析のツール：なぜなぜ分析

問題の根本原因を見つけるために「なぜ？」を5回繰り返します。

**例：「システムの処理が遅い」問題**

```
問題：システムの処理が遅い
 ↓ なぜ？
原因1：データベースへのクエリが多い
 ↓ なぜ？
原因2：N+1問題が発生している
 ↓ なぜ？
原因3：ORMの使い方を理解していなかった
 ↓ なぜ？
原因4：レビューでコードの効率性を確認する文化がなかった
 ↓ なぜ？
根本原因：開発チームにコードレビューのガイドラインがない
```

根本原因（原因4・5）を解決することで、同じ問題の再発を防げます。

### PDCAサイクル

PDCAとは、継続的な改善のためのサイクルです。

| フェーズ | 内容 |
|---------|------|
| **Plan（計画）** | 目標を設定し、達成するための計画を立てる |
| **Do（実行）** | 計画に従って行動する |
| **Check（評価）** | 結果を測定し、計画との差異を分析する |
| **Action（改善）** | 評価をもとに改善策を立て、次のPlanへ反映する |

**PDCAのポイント**

- Checkをサボると同じ失敗を繰り返す
- ActionはCheckの結果に基づく（感覚で変えない）
- 短いサイクルで素早く回す方が改善速度が上がる

### ロジカルシンキングの基本

**MECEの原則**（Mutually Exclusive, Collectively Exhaustive）

- **漏れなく・重複なく**情報を整理する
- 例：顧客を「20代・30代・40代以上」に分類する（漏れなし、重複なし）

**ロジックツリー**

問題や解決策を木の枝のように分解して整理します。

```
【売上が下がっている】
├── 新規顧客が減っている
│   ├── 認知度が低い
│   └── 競合に負けている
└── 既存顧客の離脱が増えている
    ├── 品質への不満
    └── 価格の問題
```

### 仮説思考

全データが揃うのを待たず、**仮説を立てて検証する**スタイルが仕事の速度を上げます。

1. 限られた情報から仮説を立てる
2. 仮説を検証するために必要なデータを絞る
3. 検証結果で仮説を修正する

> **ポイント：** 問題解決は「正解を探すこと」ではなく「最善策を選び、改善し続けること」です。完璧な解決策は存在しないため、素早く試して学ぶ姿勢が大切です。

## 練習問題

以下の問いに、自分の言葉で具体的に答えてください。

1. 以下の問題に対して「なぜなぜ分析」を実施し、根本原因を特定してください。根本原因に対する再発防止策も提案してください。
   - **問題：** 「プロジェクトの納期が2週間遅れた」

2. PDCAサイクルを使って、「ビジネスメールの返信が遅い（24時間以上かかることが多い）」という問題を改善する計画を作成してください。P・D・C・Aの各フェーズで何をするか具体的に示してください。

3. 「問題が発生した時、原因を探るより先に解決策を実行してしまう」ことの問題点を論理的に説明し、なぜ「原因分析」が先に来るべきかを述べてください。
