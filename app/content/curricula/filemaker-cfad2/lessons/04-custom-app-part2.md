## 1. リレーショナルデータベースの設計（FM24-2.3.9）

### 基本概念

| 概念 | 説明 |
|------|------|
| ER図 | エンティティ（テーブル）とリレーションシップを図示したもの |
| 正規化 | データの重複を排除してテーブルを整理する手法 |
| 主キー | レコードを一意に識別するフィールド（重複不可・空欄不可） |

---

## 2. リレーションシップの種類（FM24-2.3.10）

### リレーションシップの3種類

| 種類 | 例 | 実装 |
|------|-----|------|
| 1対1 | 社員 ↔ 社員詳細 | 直接リレーション |
| 1対多 | 顧客 → 注文 | 直接リレーション |
| 多対多 | 商品 ↔ 注文 | **中間テーブル**が必要 |

### 多対多の実装

多対多のリレーションシップは直接定義できません。**中間テーブル（ジョイン/連結テーブル）** を使います。

```
商品テーブル ─── 注文明細テーブル ─── 注文テーブル
（多）             （中間テーブル）          （多）
```

### 自己連結リレーションシップ

同一テーブルの別のテーブルオカレンス（TO）を作成して、テーブル自身とリレーションを定義します。
例：従業員テーブルで上司を参照するなど。

---

## 3. リレーションシップの設定オプション（FM24-2.3.11）

### [リレーションシップ編集] ダイアログの主要オプション

| オプション | 効果 |
|-----------|------|
| **[このリレーションシップを使用して、このテーブルでのレコードの作成を許可]** | 関連テーブルのポータルから新規レコードを作成できる |
| **[他のテーブルでレコードが削除された時、このテーブルの関連レコードを削除]** | 親レコード削除時に子レコードも自動削除（連鎖削除） |
| [レコードのソート] | 関連レコードの表示順を指定 |
| 複数の照合条件 | 複数フィールドの組み合わせでリレーションを定義 |

### ポータルでのレコード作成

- 「レコードの作成を許可」オプションがONのTOをポータルに設定すると、ポータルの最終行から新規レコードを作成できる

### リレーションシップのソート効果

- ポータルに表示される関連レコードのソート順が変わる
- 関連フィールドを直接配置した場合は**最初の関連レコードの値**が表示される

## 4. 外部データソース（FM24-2.3.12）

### 外部FileMakerデータソースの追加

**[ファイル] メニュー → [管理] → [外部データソース]** で設定。

| 項目 | 内容 |
|------|------|
| 外部データソース名 | 識別名 |
| タイプ | FileMaker / ODBC |
| ファイルパス | 外部ファイルの場所 |

### 保護ファイルと認証

- **保護ファイル**：外部データソースにアクセス権限を設定したファイル
- **（ファイルの）認証**：外部ファイルにアクセスする際のアカウント認証
- **固有ID**：外部ファイルを一意に識別するID

### リレーションシップグラフでの外部TO

- 外部データソースのTOはリレーションシップグラフに表示される
- 外部TOのソーステーブルは外部ファイルのテーブルになる
- 現在のファイルから外部TOのフィールドを参照するスクリプトはエラーになる**場合がある**（アクセス権による）

## 6. よく使われる FileMaker 関数（FM24-2.3.14）

### テキスト関数

| 関数 | 用途 | 例 |
|------|------|-----|
| `Substitute ( テキスト ; 検索 ; 置換 )` | 文字列の置換 | `Substitute ( "a@b" ; "@" ; "¶" )` → `"a¶b"` |
| `GetValue ( テキスト ; 行番号 )` | 改行区切りテキストから指定行を取得 | `GetValue ( "A¶B¶C" ; 2 )` → `"B"` |
| `IsEmpty ( フィールド )` | フィールドが空かどうか | `IsEmpty ( 氏名 )` |
| `Self` | 自分自身のフィールドを参照 | 計算式内でSelf（入力値の制限などで使用）|

### 論理関数

| 関数 | 用途 |
|------|------|
| `If ( 条件 ; 真 ; 偽 )` | 条件分岐（2択） |
| `Case ( 条件1 ; 結果1 ; 条件2 ; 結果2 ; ... ; デフォルト )` | 複数条件分岐 |
| `Let ( 変数名 = 値 ; 計算式 )` | 変数宣言してから計算 |
| `While ( 初期値 ; 条件 ; 処理 ; 結果 )` | ループ処理 |
| `Evaluate ( 計算式文字列 )` | 文字列を計算式として評価 |

### 取得関数（Get関数）

| 関数 | 返す値 |
|------|--------|
| `Get ( 最終エラー )` | 最後のエラー番号 |
| `Get ( 最終メッセージ )` | 最後のエラーメッセージ |
| `Get ( 日付 )` | 現在の日付 |
| `Get ( アカウント名 )` | 現在のアカウント名 |
| `Get ( スクリプト引数 )` | スクリプトに渡された引数 |

### JSON関数

| 関数 | 用途 |
|------|------|
| `JSONGetElement ( JSON ; キー )` | JSONから値を取得 |
| `JSONSetElement ( JSON ; キー ; 値 ; タイプ )` | JSONに値を設定 |
| `JSONFormatElements ( JSON )` | JSONを整形 |

### GetContainerAttribute

オブジェクトフィールドのメタデータを取得する関数。
```
GetContainerAttribute ( フィールド ; 属性名 )
```
属性名の例：`"filename"`, `"filesize"`, `"width"`, `"height"`

### Substitute + GetValue の組み合わせ（頻出）

```
GetValue ( Substitute ( 顧客::メールアドレス ; "@" ; ¶ ) ; 2 )
```
→ `connect@claris.com` の場合、`@` を改行に置換後、2行目を取得 = `claris.com`

## 7. カスタム関数（FM24-2.3.15）

### カスタム関数とは

ユーザーが独自に定義した再利用可能な計算関数。

**利点：**
- 複雑な計算式を再利用できる
- メンテナンスが集中管理できる
- 再帰処理が可能

**管理方法：**
- [ファイル] → [管理] → [カスタム関数] から開く **[カスタム関数の管理] ダイアログ**
- 他ファイルからカスタム関数を**コピー/インポート**することができる

### カスタム関数の使用と [高度なツール]

- カスタム関数の**作成・編集・管理** → [高度なツールを利用する] が必要
- カスタム関数の**使用**（呼び出し） → [高度なツールを利用する] は不要

## 例題 3-6

「親」テーブルオカレンス（TO）と「子」TO 間にリレーションシップを定義して、[レコードのソート] を選択し、「子」TO の「年齢」フィールドをソートフィールドに指定しました。

この効果について適切な記述を**すべて**選択してください。

A. 「親」TO をレイアウトテーブルとするレイアウトに「子」TO の「年齢」フィールドが直接配置されている場合、指定されたソート順で最初の関連レコードの値が表示される。

B. 「親」TO をレイアウトテーブルとするレイアウトに「子」TO の「年齢」フィールドが直接配置されている場合、指定されたソート順で最後の関連レコードの値が表示される。

C. 「親」TO をレイアウトテーブルとするレイアウトに「子」TO のポータルがデフォルトの設定で配置されている場合、[リレーションシップ編集] ダイアログボックスで指定されたソート順でポータルレコードが表示される。

D. 「子」TO のソーステーブルのレコードの順序も、指定されたソート順に変更される。

<details>
<summary>解答と解説を見る</summary>

**解答：A, C**

**解説：**
- **A（○）**：関連フィールドをレイアウトに直接配置した場合、ソート順の**最初の**関連レコードの値が表示されます。
- **B（×）**：最初の関連レコードが表示されます（最後ではありません）。
- **C（○）**：[リレーションシップ編集] でのレコードのソート設定は、ポータルのデフォルト表示に反映されます。
- **D（×）**：リレーションシップのソート設定はポータルや関連フィールドの**表示順**に影響するだけで、ソーステーブル自体のレコード順は変わりません。

**参考：**
- https://help.claris.com/ja/pro-help/content/creating-relationships.html

</details>

## 例題 3-8

「顧客::メールアドレス」フィールドの値が「connect@claris.com」の場合、以下の計算式の評価結果を選択してください。

```
GetValue ( Substitute ( 顧客::メールアドレス ; "@" ; ¶ ) ; 2 )
```

A. connect
B. claris
C. claris.com
D. connect¶claris.com
E. ?

<details>
<summary>解答と解説を見る</summary>

**解答：C**

**解説：**

ステップ1：`Substitute ( "connect@claris.com" ; "@" ; ¶ )`
→ `@` を改行（¶）に置換
→ 結果：`"connect¶claris.com"`（2行のテキスト）

ステップ2：`GetValue ( "connect¶claris.com" ; 2 )`
→ 改行区切りテキストの2行目を取得
→ 結果：`"claris.com"`

**参考：**
- https://help.claris.com/ja/pro-help/content/substitute.html
- https://help.claris.com/ja/pro-help/content/getvalue.html

</details>

## 例題 3-9

次のようなカスタム関数があります。

```
CF_CalcAge ( Birthday ; TheDate ) =
  Let (
    BaseDate = Case ( IsEmpty ( TheDate ) ; Get ( 日付 ) ; TheDate ) ;
    Year ( BaseDate ) - Year ( Birthday )
      - ( BaseDate < Date ( Month ( Birthday ) ; Day ( Birthday ) ; Year ( BaseDate ) ) )
  )
```

日付フィールド「日付 1」および「日付 2」にそれぞれ値「2000/12/1」、「2025/1/1」が保存されていたとき、次の計算式から返される値を選択してください。なお、本日の日付は「2024/11/30」とします。

```
CF_CalcAge ( 日付 1 ; 日付 2 )
```

A. 23
B. 24
C. 25
D. 26

<details>
<summary>解答と解説を見る</summary>

**解答：B**

**解説：**

- `Birthday = 2000/12/1`、`TheDate = 2025/1/1`
- `IsEmpty ( TheDate )` → 2025/1/1は空でないのでFalse
- `BaseDate = 2025/1/1`

年齢計算：
- `Year ( 2025/1/1 ) - Year ( 2000/12/1 )` = `2025 - 2000` = `25`
- 誕生日チェック：`2025/1/1 < Date ( 12 ; 1 ; 2025 )` = `2025/1/1 < 2025/12/1` → True（1）
- 結果：`25 - 1` = **24**

（TheDate = 2025/1/1 の時点では、Birthday = 12/1 の誕生日がまだ来ていないため、24歳）

**このカスタム関数のポイント：**
- `Let` で変数 `BaseDate` を定義して計算を簡潔にしている
- `IsEmpty` でデフォルト値（今日の日付）を設定している
- 誕生日前後の判定で1を減算している

</details>
