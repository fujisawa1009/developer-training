## 1. カスタム App の開発手順（FM24-2.3.1）

### 開発フロー

```
① 企画         → 目的・対象ユーザーの整理
② 要件定義     → 必要な機能・データの洗い出し
③ データベース設計 → テーブル・フィールド・リレーションシップの設計
④ 画面設計     → レイアウト・UI設計
⑤ 機能設計     → スクリプト・計算式の設計
⑥ テスト       → 動作確認・デバッグ
```

### 共有利用するカスタム App の設計ポイント

- 業務フローに合わせた、誰もが簡単に操作できるインタフェース
- マスタデータを誤変更・削除されないようにアクセス権を設定
- バックアップの手段と運用方法を用意

> **注意：** 全員に管理者権限を付与するのは**不適切**。アクセス権で適切な権限を設定すること。

## 2. 計算フィールドのオプション（FM24-2.3.2）

### 計算フィールドの特性

| 特性 | 内容 |
|------|------|
| フィールド値のタイプ | [計算結果] で指定できる（テキスト、数字、日付など） |
| 索引オプション | 索引を設定すると再計算タイミングが変わる |
| 関連フィールド参照 | 計算式に関連フィールドが含まれる場合、フィールド値を**保存できない** |

### 再計算のタイミング

| 条件 | 再計算タイミング |
|------|--------------|
| 索引オプション：なし | 常に動的に計算（表示のたびに計算） |
| 索引オプション：あり | 参照フィールドの値が変わったときに再計算・保存 |

> **試験頻出：** 計算式に**関連フィールドへの参照が含まれている場合は、フィールド値を保存できない**。

## 3. 集計レポートの作成（FM24-2.3.3）

### 集計用レイアウトパートの種類

| パート | 用途 |
|-------|------|
| 総計パート（前部/後部） | 全レコードの総計を表示 |
| 小計パート（前部/後部） | グループごとの小計を表示 |
| ボディ | 個々のレコードを表示 |

### 集計レポート作成の手順

1. 集計フィールドを作成（集計タイプ）
2. 小計パートを作成し、区分けフィールドを設定
3. 小計パートに集計フィールドを配置
4. ブラウズモードで区分けフィールドでソート

## 4. 入力値の自動化（FM24-2.3.4）

### 主要オプションと特性

| オプション | 動作のタイミング | 特性 |
|-----------|--------------|------|
| [シリアル番号] | レコード作成時 | 連番を自動入力 |
| [作成情報] | レコード作成時 | 作成日時・作成者を記録 |
| [修正情報] | レコード更新時 | 更新日時・更新者を記録 |
| [計算値] | 条件に応じて | 計算式で値を自動入力 |
| [ルックアップ値] | 参照フィールド変更時 | 関連レコードから値をコピー（スナップショット） |

### 重要なオプションの詳細

**[フィールドに既存の値が存在する場合は置き換えない]：**
- チェックON：既に値があれば自動入力しない
- チェックOFF：既存の値も上書きして自動入力

**[データ入力時の値変更の禁止]：**
- ユーザーが手動でフィールドを変更できなくなる

**[ルックアップ値] の特徴：**
- 参照元の値を**コピー**する（以後、参照元が変わっても自動更新されない）
- グローバル変数との違い：ルックアップは関連レコードからの一方向コピー

---

## 5. 入力値の制限（FM24-2.3.5）

### 制限のタイミング

| タイミング | 説明 |
|-----------|------|
| [常時] | スクリプトによる変更も含め、常に制限を適用 |
| [データの入力時のみ] | ユーザーがフィールドに直接入力するときのみ |
| [データの入力時にユーザによる上書きを許可する] | 警告を表示するが、ユーザーが無視して保存できる |

### 主な制限オプション

| オプション | 説明 |
|-----------|------|
| [空欄不可] | 空のままの確定を禁止 |
| [ユニークな値] | 重複する値を禁止 |
| [計算式で制限] | 計算式がTrueの場合のみ許可 |
| [最大文字数] | 文字数の上限 |
| [制限値以外の入力時にカスタムメッセージを表示] | 制限違反時のメッセージをカスタマイズ |

## 6. グローバルフィールド（FM24-2.3.6）

### グローバルフィールドの特性

- **全レコードで同じ値を共有**（テーブル内の全レコードに1つの値）
- ファイルを閉じると初期値に戻る（共有ファイルの場合）
- 検索条件には使用できない（グローバル格納フィールドは検索対象外）
- スクリプトの一時的な値の格納場所として活用

### グローバル変数（$$変数）との違い

| 項目 | グローバルフィールド | グローバル変数（$$変数） |
|------|------------------|---------------------|
| スコープ | ファイル内全体 | ファイル内全体（スクリプト間を超える） |
| 永続性 | ファイルを閉じると初期化 | ファイルを閉じると消える |
| データベース設計 | テーブルのフィールドとして定義 | スクリプト内で宣言 |
| 検索 | 検索不可 | 使用不可 |

## 7. 索引（FM24-2.3.7）

### 索引の種類

| 種類 | 対象 | 用途 |
|------|------|------|
| 値の索引 | フィールド全体の値 | 完全一致検索、ソート |
| 単語の索引 | テキストの単語単位 | 単語検索、オートコンプリート |

### 索引設定オプション

| 設定 | 動作 |
|------|------|
| [なし] | 索引なし。ファイルサイズ最小だが検索・ソートが遅い |
| [最小限] | 値の索引のみ（テキストは値の索引） |
| [すべて] | 値の索引と単語の索引の両方 |
| [必要時に索引を自動設定] | 初めて検索されたときに自動で索引を作成 |

**[必要時に索引を自動設定]：**
- 最初に検索が実行されたとき、索引が[最小限]に変わる
- その後は索引が維持される

### 計算フィールドの索引

- 関連フィールドを参照する計算フィールドは**索引を設定できない**
- 索引が設定されると再計算タイミングが変わる

---

## 8. オブジェクトデータの格納（FM24-2.3.8）

### 格納方法の種類

| 方法 | 特性 |
|------|------|
| 埋め込み | ファイル内に直接保存。ファイルサイズが大きくなる |
| 外部保存（セキュア格納） | 暗号化して外部フォルダに保存。安全だが外部参照 |
| 外部保存（オープン格納） | 暗号化なしで外部フォルダに保存。ファイルとして直接アクセス可能 |

### 外部保存の設定

- **[基本ディレクトリ]**：外部保存の基準となるフォルダ（FileMaker Pro の環境設定で設定）
- **セキュア格納**：オブジェクトデータファイルが暗号化される
- **オープン格納**：基本ディレクトリ以下の保存ディレクトリを指定できる
- **グローバル格納 + 外部保存**：グローバル格納と外部保存を同時指定すると**自動的にセキュア格納**になる

### Transfer.log

- オブジェクトデータを外部に転送した結果を確認できるログファイル

## 例題 3-2

計算タイプのフィールド（計算フィールド）について、適切な記述を選択してください。

A. フィールド値のタイプは計算式の内容で自動設定され、ユーザは指定できない。
B. 計算式に関連フィールドへの参照が含まれている場合は、フィールド値を保存できない。
C. 計算式の中でグローバルフィールドの値を使うことはできない。
D. フィールドに索引オプションが設定されているときと設定されていないときとで、計算式が再計算されるタイミング（きっかけ）は常に同じである。

<details>
<summary>解答と解説を見る</summary>

**解答：B**

**解説：**
- **A（×）**：計算フィールドの [計算結果] でデータタイプをユーザが指定できます（テキスト、数字、日付など）。
- **B（○）**：計算式に関連フィールドへの参照が含まれている場合、フィールド値を保存できません（保存なし設定になります）。

- **D（×）**：索引オプションの有無で再計算タイミングが異なります。索引なしは動的計算、索引ありは変更検知時に再計算します。

## 例題 3-3

FileMaker Pro ファイルでテーブルを新規作成したときに自動生成される「作成者」フィールドには、次のフィールドオプションが設定されています。

- 入力値の自動化：[作成情報] [アカウント名]、[データ入力時の値変更の禁止] チェックあり
- 入力値の制限：[データの入力時のみ]、[空欄不可]、[ユニークな値]

この設定のままの「作成者」フィールドについて、適切な記述を選択してください。

A. レコード生成時に、[環境設定] ダイアログの [一般] タブの [ユーザ名] に設定された値が保存される。
B. 自動入力されたフィールド値は、[完全アクセス] 権が付与されたアカウントでしか変更できない。
C. レコードの内容が更新された時は、Get (アカウント名) 関数で取得できるものと同じ値が保存される。
D. このフィールドはテーブルから削除することができる。

<details>
<summary>解答と解説を見る</summary>

**解答：D**

**解説：**
- **A（×）**：[作成情報] [アカウント名] はアカウント名を保存します。[ユーザ名] ではありません。アカウント名と [環境設定] の [ユーザ名] は別物です。
- **B（×）**：[データ入力時の値変更の禁止] があっても、[完全アクセス] ならフィールド定義からは変更できますが、通常のブラウズモードからの変更を禁止するものです。制限の種類によって動作が異なります。
- **C（×）**：[作成情報] は**レコード生成時**の情報を保存します。更新時に変わるのは [修正情報] です。
- **D（○）**：自動生成されたフィールドであっても、テーブルから削除することは可能です。

</details>

## 試験対策メモ

```
計算フィールドの落とし穴
  [計算結果]タイプ → ユーザが指定できる（自動じゃない）
  関連フィールド参照 → 値を保存できない
```
