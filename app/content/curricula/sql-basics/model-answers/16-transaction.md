## 練習問題 模範解答

### 問題1: トランザクションで2テーブルを同時更新

```sql
BEGIN;

-- 1. 注文を追加
INSERT INTO orders (user_id, product_id, quantity)
VALUES (1, 3, 2)
RETURNING id;

-- 2. 在庫を減らす
UPDATE products
SET stock = stock - 2
WHERE id = 3;

-- 結果を確認してから確定（問題なければCOMMIT、間違えたらROLLBACK）
COMMIT;
-- ROLLBACK;  ← 間違いに気づいた場合はこちら
```

**安全な手順:**
`BEGIN` → 処理 → 結果確認 → `COMMIT` / `ROLLBACK` のフローを守る。

---

### 問題2: ROLLBACK しないと起きる問題

`orders` への INSERT は成功したが、`products.stock` の UPDATE が何らかの理由で失敗した場合、ROLLBACKしないと:

- 注文レコードは存在する（在庫が引かれていないのに）
- 実際には存在しない在庫の注文が通ってしまう

→ データの整合性が崩れる。「注文は入ったのに商品の在庫が減っていない」という矛盾した状態が本番DBに残る。

ROLLBACKすることで、INSERT も UPDATE も「なかったこと」になり、整合性が保たれる。

### 問題3: 原子性・耐久性の説明（送金処理の例）

**原子性（Atomicity）:**
送金処理では「Aさんの口座から10000円を引く」「Bさんの口座に10000円を足す」という2つの操作が必要。原子性とは、この2つが「両方成功するか、両方失敗するか（どちらか一方だけ実行されない）」を保証する性質。Aさんの残高が減ってBさんに届かない状態が生じないよう、全操作を1つの単位として扱う。

**耐久性（Durability）:**
COMMITが完了した後にサーバークラッシュが起きても、送金が完了したというデータは失われないことを保証する性質。ディスクへの書き込みやWAL（Write-Ahead Log）によってCOMMIT済みデータの永続性が担保される。「送金完了」画面を見せた後に停電が起きても、データは保存されている。
