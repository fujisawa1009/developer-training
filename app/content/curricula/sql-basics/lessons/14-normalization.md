## 正規化とは

テーブル設計において**データの重複や矛盾を排除する**ための手法です。

### 正規化されていない例

1つのテーブルに全て入れた場合：

```text
orders テーブル（非正規化）
┌────┬──────┬────────────────────┬──────────┬────────┐
│ id │ 顧客名│ 顧客メール          │ 商品名    │ 金額   │
├────┼──────┼────────────────────┼──────────┼────────┤
│  1 │ 山田 │ yamada@example.com │ ノートPC │  80000 │
│  2 │ 山田 │ yamada@example.com │ マウス   │   2000 │
│  3 │ 田中 │ tanaka@example.com │ ノートPC │  80000 │
└────┴──────┴────────────────────┴──────────┴────────┘
```

問題点：
- **更新時の矛盾**：山田のメールを変更すると2行を修正する必要がある
- **データの重複**：「ノートPC = 80000円」が複数行に存在する
- **削除時の情報消失**：田中の注文を削除すると田中の情報自体も消える

### 第1正規形：繰り返しグループの排除

1つのセルに複数の値を入れない。

```text
❌ 非正規形
┌────┬──────┬──────────────────┐
│ id │ 名前 │ 電話番号          │
├────┼──────┼──────────────────┤
│  1 │ 山田 │ 090-1234, 03-5678│  ← 1セルに2つの値
└────┴──────┴──────────────────┘

✅ 第1正規形
┌────┬──────┬─────────────┐
│ id │ 名前 │ 電話番号     │
├────┼──────┼─────────────┤
│  1 │ 山田 │ 090-1234    │
│  1 │ 山田 │ 03-5678     │
└────┴──────┴─────────────┘
```

### 第2正規形：部分関数従属の排除

主キーの一部だけに依存するカラムを別テーブルに分離する。

### 第3正規形：推移関数従属の排除

主キー以外のカラムに依存するカラムを別テーブルに分離する。

### 正規化した結果

```sql
-- ユーザーテーブル
CREATE TABLE users (
  id    SERIAL PRIMARY KEY,
  name  VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL
);

-- 商品テーブル
CREATE TABLE products (
  id    SERIAL PRIMARY KEY,
  name  VARCHAR(200) NOT NULL,
  price INTEGER NOT NULL
);

-- 注文テーブル（外部キーで参照）
CREATE TABLE orders (
  id         SERIAL PRIMARY KEY,
  user_id    INTEGER REFERENCES users(id),
  product_id INTEGER REFERENCES products(id),
  quantity   INTEGER DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

メリット：
- データの重複がない
- 更新は1箇所だけで済む
- 削除しても他の情報に影響しない

> ポイント：実務では第3正規形まで意識すれば十分です。パフォーマンス上の理由であえて非正規化することもありますが、まずは正規化を理解しましょう
