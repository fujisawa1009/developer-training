## テーブルの構造

リレーショナルデータベースでは、データを**行（レコード）**と**列（カラム）**で管理します。

### 基本用語

```
            カラム（列）
            ↓
┌────┬──────┬────────────────────┐
│ id │ name │ email              │  ← 行（レコード）
├────┼──────┼────────────────────┤
│  1 │ 山田 │ yamada@example.com │  ← 行（レコード）
│  2 │ 田中 │ tanaka@example.com │  ← 行（レコード）
└────┴──────┴────────────────────┘
```

| 用語 | 意味 |
|------|------|
| テーブル | データを格納する表 |
| カラム（列） | データの項目（名前・メールなど） |
| レコード（行） | 1件のデータ |
| 主キー（PRIMARY KEY） | 各行を一意に識別する列（通常は `id`） |

### データ型

カラムにはデータの種類を指定します。

| データ型 | 説明 | 例 |
|---------|------|-----|
| `INTEGER` | 整数 | 1, 42, -10 |
| `VARCHAR(n)` | 可変長文字列（最大n文字） | 'yamada' |
| `TEXT` | 長い文字列 | 説明文など |
| `BOOLEAN` | 真偽値 | true / false |
| `TIMESTAMP` | 日時 | 2025-04-01 09:00:00 |
| `DECIMAL(p,s)` | 精密な小数 | 1234.56 |

### 制約

データの正しさを保証するルールです。

```sql
CREATE TABLE users (
  id       SERIAL PRIMARY KEY,       -- 主キー（自動採番）
  name     VARCHAR(100) NOT NULL,    -- NULLを許可しない
  email    VARCHAR(255) UNIQUE,      -- 重複を許可しない
  role     VARCHAR(20) DEFAULT 'learner'  -- 初期値を設定
);
```

| 制約 | 意味 |
|------|------|
| `PRIMARY KEY` | 主キー（NOT NULL + UNIQUE） |
| `NOT NULL` | NULL（空）を許可しない |
| `UNIQUE` | 重複する値を許可しない |
| `DEFAULT` | 値を指定しない場合の初期値 |
| `FOREIGN KEY` | 他のテーブルの主キーを参照 |

> ポイント：テーブル設計の段階で適切な制約をつけることが、データの品質を守る第一歩です
