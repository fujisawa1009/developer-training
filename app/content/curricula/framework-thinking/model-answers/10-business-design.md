## レッスン10 模範解答：事業・プロダクトを設計する（ビジネスモデルキャンバス / バリューチェーン / JTBD / PMF）

---

### 問題1：JTBD分析

**題材A：コーヒーショップ（平日朝の通勤途中に立ち寄る人）**

| 層 | ジョブ |
|---|---|
| **機能的ジョブ** | カフェインを摂取して眠気を払い、仕事に備えるためのコーヒーを素早く手に入れる |
| **感情的ジョブ** | 「今日も一日頑張れる」という気持ちの切り替えと、朝のルーティンによる安心感・落ち着きを得たい |
| **社会的ジョブ** | スタバのカップを持ち歩くことで「おしゃれ・意識が高い」という印象を周囲に与えたい |

**プロダクト改善案（コーヒーショップ）：**

感情的ジョブに着目すると「朝の気持ちの切り替え」がコア。単なるコーヒー提供にとどまらず、スタッフによる一言声かけ・名前を呼ぶサービス・季節限定のメッセージカードなど、「特別感と習慣化」を強化するオペレーション設計をすることで、ロイヤルカスタマーを増やせる。

---

**題材B：タスク管理アプリ（TodoリストのSaaS）**

| 層 | ジョブ |
|---|---|
| **機能的ジョブ** | やるべきタスクを記録・整理して、忘れたり抜け漏れが起きたりしないようにする |
| **感情的ジョブ** | タスクが頭の中から出てスッキリした状態で仕事に集中したい。完了チェックで「やり切った達成感」を感じたい |
| **社会的ジョブ** | 「仕事ができる整理された人」として同僚や上司から見られたい |

**プロダクト改善案（タスク管理アプリ）：**

感情的ジョブ（達成感・集中）に着目すると、タスク完了時のアニメーションや「今日のタスクを全部終えた」ときの祝福メッセージなど、達成感を強化するUXを強化することで継続利用率と口コミにつながる。

> **採点ポイント**：3層（機能的・感情的・社会的）が正しく区別されているか。「本当に達成したいこと」が「機能的ジョブ」より深い層で表現されているか。改善案がJTBD分析から論理的に導かれているかがポイント。

### 問題2：ビジネスモデルキャンバス（フリーランスエンジニアと企業のマッチングプラットフォーム）

| ブロック | 内容 |
|---|---|
| **CS（顧客セグメント）** | ①スタートアップ・中小企業の開発責任者（エンジニア採用が難しい企業）②フリーランスエンジニア（案件を継続的に獲得したい個人） |
| **VP（価値提案）** | 企業向け：採用コスト・時間をかけずに即戦力エンジニアとプロジェクト単位で契約できる。エンジニア向け：営業不要で自分のスキルに合った案件を継続的に獲得できる |
| **CH（チャネル）** | 企業向け：Webサイト・営業アウトバウンド・SNS広告。エンジニア向け：技術コミュニティ・SNS（Twitter/X・Zenn）・紹介 |
| **CR（顧客関係）** | 企業向け：カスタマーサクセス担当者による定期フォロー。エンジニア向け：セルフサービス（案件検索・応募は自律的に） |
| **R$（収益の流れ）** | 企業向けの月額掲載料（固定収益）+ 成約時の成功報酬（報酬額の15%） |
| **KR（主要リソース）** | エンジニアのタレントデータベース・スキル評価システム・マッチングアルゴリズム・カスタマーサクセスチーム |
| **KA（主要活動）** | エンジニアのスカウト・審査・プロフィール管理、企業への提案・マッチング、決済・契約管理 |
| **KP（主要パートナー）** | 技術コミュニティ・エンジニアスクール（人材パイプライン）・決済サービス会社 |
| **C$（コスト構造）** | エンジニア審査・オンボーディングコスト・システム開発・保守費・カスタマーサクセス人件費・マーケティング費 |

**CSとVPの整合性確認：**

企業CSには「即戦力エンジニアとの柔軟な契約」、エンジニアCSには「案件の継続獲得」というVPがそれぞれ対応しており、双方の課題を解決するプラットフォーム価値として整合している。

> **採点ポイント**：9ブロックが漏れなく埋められているか。CSが2セグメント（企業・エンジニア）で設定されているか。VPが各CSの課題に対応した形で述べられているか。収益モデルが明確かがポイント。
