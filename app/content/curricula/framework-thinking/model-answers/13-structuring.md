## 課題13 模範解答：構造化思考と問題深掘り（MECE・ロジックツリー・なぜなぜ分析）

---

### 問題1：ロジックツリー（Whyツリー）

**問題：「ECサイトの購入完了率が先月比15%低下した」**

```
購入完了率が低下した
├── カート追加後に離脱している（途中離脱の増加）
│   ├── 購入フロー（決済画面）での離脱
│   │   ├── 決済方法の選択肢が少ない
│   │   ├── 入力フォームが長い・エラーが出やすい
│   │   └── セキュリティへの不安（鍵マークなし・信頼感の欠如）
│   └── カート確認画面での離脱
│       ├── 送料・手数料が高く驚く（価格の透明性が低い）
│       └── 「後で買う」行動が増えている
└── カート追加自体が減っている（カート前段階の変化）
    ├── 商品ページのCVRが低下している
    │   ├── 商品情報・画像の質が低い
    │   └── 価格競争力が弱い
    └── 流入ユーザーの質が変化している
        ├── 広告施策変更による非購買層の増加
        └── 季節性・外部要因による購買意欲の低下
```

**なぜこの分け方はMECEか**：「購入完了率 = カート追加率 × カートから購入への転換率」という数式に基づき、「カート追加後の離脱」と「カート追加前の変化」に分けた。この2つは重複せず、合わせると購入完了率の全要因を網羅する。

### 問題2：なぜなぜ分析

**選んだ原因**：「決済画面での入力フォームが長く、エラーが出やすい」

```
なぜ購入完了率が下がったのか？
  → 決済画面でユーザーが離脱しているから

なぜ決済画面で離脱するのか？
  → 入力フォームが長くて複雑で、途中で諦めるから

なぜフォームが長くて複雑なのか？
  → 必須入力項目が多すぎるから（住所・電話番号・カード情報など）

なぜ必須項目が多すぎるのか？
  → 2年前のシステム設計から見直されていないから

なぜ見直されていないのか？
  → 決済フロー改善を担当するチームがなく、優先度が低く放置されてきたから
```

**根本原因**：決済UXを継続的に見直す担当チームと改善プロセスが存在しない

**具体的な解決策**：
1. 短期：フォームの必須項目を最低限に絞り込む（住所入力の簡略化・自動補完の導入）
2. 中期：決済フロー改善を専任で担当するPdMとエンジニアを1名ずつ任命し、四半期ごとの改善レビューを制度化する

### 問題3：ピラミッドストラクチャーと報告文

**ピラミッドストラクチャー**

```
【結論】
決済フォームの入力体験改善を最優先課題として取り組むべきです

【根拠1】カート離脱の主因は決済フォームの複雑さにある
  ├── ヒートマップ上、決済画面での離脱率が最も高い
  └── フォームのエラー発生率が先月比で20%上昇している

【根拠2】改善コストに対して期待ROIが高い
  ├── 入力項目の削減はフロントエンド改修のみで完結する
  └── 同業他社の事例では、フォーム改善でCVRが10〜20%向上した実績がある

【根拠3】現在の体制に構造的な課題がある
  ├── 決済フロー改善の担当者・プロセスが存在しない
  └── 最後のフォーム改修は2年以上前で、UXレビューが機能していない
```

**報告文（SCQA構造）**

先月、ECサイトの購入完了率が前月比で15%低下しました（S：状況）。このまま放置すると月次売上への影響が継続するため、早急な対策が必要です（C：問題）。原因を分析した結果、「決済フォームの複雑さが離脱の主因」であることが判明しました（Q：問い）。ついては、フォームの入力項目削減を最優先で実施し、並行して決済UXの継続改善プロセスを整備することを提案します（A：解決策）。改善後のCVR回復を毎週モニタリングし、1ヶ月以内に効果検証を行います。

---

### 採点ポイント

- ロジックツリーの最初の分岐がMECEになっており、その根拠を数式・概念で説明できているか
- なぜなぜ分析が「人のせい」「気合不足」ではなく「プロセス・仕組みの問題」に辿り着いているか
- ピラミッドの結論が「分析の結論」として論理的に導かれているか
- 報告文にSCQAの流れが明確にあるか
