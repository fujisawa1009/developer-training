## 改善を「仕組み化」する

一度の施策で成果が出ることは稀です。ビジネスで成果を出し続けるには、**継続的に改善するサイクルを仕組みとして回すこと**が不可欠です。このレッスンでは、改善・目標管理の代表的な4つのフレームワークを学びます。

---

## PDCAサイクル

**PDCA**は最も広く使われている継続改善サイクルです。

```
      ┌──── Plan ────┐
      │   (計画する)   │
      ▼               │
   Act ◄──────────► Do
 (改善する)         (実行する)
      ▲               │
      │   Check       │
      └────(検証する)──┘
```

### 各ステップの内容

| ステップ | 内容 | 問い |
|---|---|---|
| **Plan（計画）** | 目標と施策を設定する | 何を・いつまでに・どうやって達成するか |
| **Do（実行）** | 計画を実行する | 記録・ログを取りながら実施する |
| **Check（検証）** | 結果を計画と比較する | 目標に対してどれだけ達成できたか |
| **Act（改善）** | 問題点を修正・次に活かす | 何が原因で・次回どう変えるか |

### PDCAを機能させるポイント

- **計画（P）の質が全てを決める**：目標が曖昧だとCheckができない
- **Check（C）はデータに基づく**：感覚ではなく事実で判断する
- **Act（A）を次のPlanに反映する**：ループを止めない

### PDCAの限界

PDCAは「計画通りに動ける環境」に適しています。変化が速い環境では、計画に固執しすぎると機会を逃すことがあります。

## OODAループ

**OODAループ**は、不確実・高速な環境での意思決定サイクルです。元々は米軍パイロットのジョン・ボイドが考案した戦略理論で、スタートアップや緊急対応にも使われます。

```
Observe → Orient → Decide → Act
（観察）  （解釈）  （決断）  （行動）
    ▲                           │
    └───────────────────────────┘
               フィードバック
```

### 各ステップ

| ステップ | 内容 |
|---|---|
| **Observe（観察）** | 現状の情報をありのまま集める |
| **Orient（解釈）** | 集めた情報を解釈し、状況を理解する |
| **Decide（決断）** | とるべき行動を選択する |
| **Act（行動）** | すばやく実行し、結果を観察に戻す |

### PDCAとOODAの比較

| 比較軸 | PDCA | OODA |
|---|---|---|
| 前提 | 計画通りに動ける環境 | 不確実・変化の速い環境 |
| 重点 | 計画と実行の精度 | 観察と解釈のスピード |
| 強み | 品質・効率の継続改善 | 素早い意思決定・適応 |
| 例 | 生産管理・業務改善 | スタートアップ・危機対応 |

> 安定した業務改善にはPDCA、変化への対応にはOODAを使い分けるとよい。

## OKR（Objectives and Key Results）

**OKR**は、GoogleやIntelが普及させた目標管理フレームワークです。組織・チーム・個人の目標を「Objective（目標）」と「Key Results（主要な成果）」でシンプルに管理します。

### OKRの構造

```
Objective（目標）
  「何を達成したいか」を定性的・野心的に表現する

Key Results（主要な成果）
  「どうなれば達成したと言えるか」を定量的・測定可能に表現する（3〜5個）
```

### OKRの例

> **Objective**: ユーザーに愛されるプロダクトを作る
>
> **Key Results**:
> - NPS（顧客推奨度）を30→50に改善する
> - 月次アクティブユーザーを10,000人→15,000人に増やす
> - 解約率を5%→3%以下に下げる

### OKRのポイント

| 特徴 | 説明 |
|---|---|
| 野心的な目標 | 100%達成より60〜70%の達成率を理想とする（stretch goal） |
| 透明性 | 組織全員が互いのOKRを見られる |
| 短いサイクル | 通常は四半期単位で設定・評価する |
| KPIとの違い | OKRは「変革・成長目標」、KPIは「業務管理指標」 |

## KPIツリー

**KPIツリー**は、最終目標（KGI）を達成するために必要なKPI（重要業績指標）をツリー状に展開したフレームワークです。どの指標を改善すれば最終目標に近づくかを明確にします。

### KGIとKPIの関係

```
KGI（Key Goal Indicator）
  └── 最終的に達成したい目標指標（例：月次売上 1,000万円）

KPI（Key Performance Indicator）
  └── KGIを達成するための中間指標（例：新規顧客数・客単価）
```

### KPIツリーの例（ECサイトの売上向上）

```
月次売上（KGI）
├── 新規顧客売上
│   ├── 新規訪問者数
│   │   ├── 広告クリック数
│   │   └── オーガニック流入数
│   └── 新規CVR（コンバージョン率）
│       ├── LP改善
│       └── フォーム完了率
└── 既存顧客売上
    ├── リピート率
    │   ├── メルマガ開封率
    │   └── リターゲティング効果
    └── 客単価
        ├── アップセル率
        └── クロスセル率
```

### KPIツリーの活用

1. 売上・利益などのKGIからツリーを展開する
2. 各KPIを数式で表せるか確認する（数式ツリーを作る）
3. インパクトが大きく・コントロールできるKPIを重点的に管理する

## フレームワーク選択ガイド

| 用途 | おすすめ |
|---|---|
| 業務・プロセスを継続的に改善する | PDCA |
| 不確実な環境で素早く動く | OODAループ |
| 組織・チームの方向性を揃える | OKR |
| 目標を指標に落とし込む | KPIツリー |

## 練習問題

### 問題1：PDCAサイクルの設計

以下のシナリオに対して、PDCAの各ステップを設計してください。

**シナリオ：**
あなたはWebメディアの編集担当者です。記事のSNSシェア数を増やすことが今月の目標ですが、先月は目標の50%しか達成できませんでした。来月に向けてPDCAを回すことになりました。

- **Plan（計画）**：目標数値と実施する施策（2〜3つ）を設定してください
- **Do（実行）**：実行時に記録・ログとして残すべき指標を2〜3つ挙げてください
- **Check（検証）**：「施策が効いたかどうか」を判断するための比較基準を説明してください
- **Act（改善）**：施策が効かなかった場合に考えられる次の改善アクションを1つ述べてください

---

### 問題2：OKRの設定

以下のテーマでOKR（Objective + Key Results 3つ）を設定してください。

**テーマ：あなた自身の「今後3ヶ月のエンジニアとしての成長」**

- Objective：野心的・定性的な目標を1文で記述してください
- Key Results：Objectiveの達成を測定できる定量的な指標を3つ設定してください（具体的な数値目標を含めること）

設定後、「このOKRはなぜKPIではなくOKRとして設定するのか」を1〜2文で述べてください。
