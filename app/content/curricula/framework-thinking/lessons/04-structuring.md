## なぜ「構造化」が重要か

情報が散らばっていると、問題の全体像が見えず、抜け漏れが生じ、相手に伝わりません。**構造化**とは情報をツリー状・階層状に整理することで、**思考の整理・伝達・意思決定**を効率化するスキルです。

---

## MECE（ミーシー）

**MECE（Mutually Exclusive, Collectively Exhaustive）**は「漏れなく・ダブりなく」という原則です。コンサルティングの現場で最も重視される思考の基本ルールです。

```
Mutually Exclusive   → 互いに重複しない（ダブりなし）
Collectively Exhaustive → 全体を網羅している（漏れなし）
```

### MECEのイメージ

```
【ダブりあり ❌】         【漏れあり ❌】         【MECE ✅】
  ┌───┐ ┌───┐           ┌───┐ ┌───┐          ┌───┐ ┌───┐
  │ A │ │ B │           │ A │ │ B │          │ A │ │ B │
  │  ┌┼─┼┐ │           │   │ │   │          │   │ │   │
  └──┼┼─┼┼─┘           └───┘ └───┘          └───┘ └───┘
     └┘ └┘              ・・・ ← 隙間がある     全体 = A + B
  重複している           漏れている            完全に分割
```

### MECEの作り方

**1. 対概念で分ける**
- 国内 ／ 海外
- 新規顧客 ／ 既存顧客
- オンライン ／ オフライン

**2. プロセスで分ける**
- 認知 → 検討 → 購入 → 継続

**3. 既存フレームワークを借りる**
- 3C・4P・PEST などの分類軸はMECEに設計されている

> MECEは「完璧を求めすぎない」ことも大切。実務では「ほぼMECE」で十分なことが多い。

## ロジックツリー

**ロジックツリー**は、問題・課題・原因・解決策を「ツリー状」に展開していくフレームワークです。MECEを守りながら分解することで、思考を網羅的・論理的に整理できます。

### 3種類のロジックツリー

| 種類 | 目的 | 問い |
|---|---|---|
| **Whatツリー** | 問題・構成要素の分解 | 「これは何で構成されているか？」 |
| **Whyツリー** | 原因・背景の分析 | 「なぜこうなっているのか？」 |
| **Howツリー** | 解決策・打ち手の展開 | 「どうすれば解決できるか？」 |

### ロジックツリーの例（売上低下の原因分析 / Whyツリー）

```
売上が低下している
├── 顧客数が減っている
│   ├── 新規顧客の獲得が減っている
│   │   ├── 認知度が下がっている
│   │   └── 競合に流れている
│   └── 既存顧客が離脱している
│       ├── 満足度が低下している
│       └── 解約率が上昇している
└── 客単価が下がっている
    ├── 購入点数が減っている
    └── 値下げの影響
```

### ロジックツリーを作るコツ

1. 最初の分岐を慎重に決める（MECEを守る）
2. 各枝を同じ粒度で展開する
3. 「So what?」「Why so?」を繰り返す
4. 具体的なアクションが見えるまで掘り下げる

## ピラミッドストラクチャー

**ピラミッドストラクチャー**は、結論（主張）を頂点に置き、その根拠・論拠をピラミッド状に積み上げる構造です。**論理的な文書・プレゼン・説明**に欠かせないフレームワークです。

### 基本構造

```
            ┌─────────┐
            │  結論   │ ← 最初に言う
            └────┬────┘
       ┌─────────┼─────────┐
       ▼         ▼         ▼
   ┌───────┐ ┌───────┐ ┌───────┐
   │ 根拠1 │ │ 根拠2 │ │ 根拠3 │ ← Why so?
   └──┬────┘ └──┬────┘ └──┬────┘
   ┌──┴──┐   ┌──┴──┐   ┌──┴──┐
   │データ│   │データ│   │データ│ ← 事実・根拠
   └─────┘   └─────┘   └─────┘
```

### SCQA構造と組み合わせる

プレゼンや報告書では、**SCQA**フレームと組み合わせると効果的です。

| 要素 | 内容 | 例 |
|---|---|---|
| S（Situation） | 前提・状況の共有 | 「先月の売上は前年比10%減でした」 |
| C（Complication）| 問題・課題 | 「このままでは年間目標を達成できません」 |
| Q（Question） | 解くべき問い | 「どうすれば売上を回復できるか？」 |
| A（Answer） | 結論・提案 | 「新規顧客獲得施策を強化するべきです」 |

### ピラミッドの2パターン

**演繹型（Why so?）**：結論から根拠を積み上げる
- 「提案：〇〇すべき → 理由1・理由2・理由3」
- 説得・提案に向いている

**帰納型（So what?）**：事実から結論を導く
- 「事実1・事実2・事実3 → 結論：〇〇と言える」
- 分析・報告に向いている

---

## 3つのフレームワークの関係

```
MECE ──────────────────────→ 「考え方の原則」
                              ↗
ロジックツリー ──────────→ 「原因・解決策を分解する道具」
                              ↗
ピラミッドストラクチャー → 「伝える・説明する道具」
```

> この3つをマスターすれば、「考える」「整理する」「伝える」の全てが格段に上がります。まずはロジックツリーを紙に書く練習から始めましょう。
