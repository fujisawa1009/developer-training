## フレームワーク思考とは

**フレームワーク思考**とは、複雑な問題や状況を整理・分析するための「型（フレームワーク）」を使って考える思考法です。

白紙から考え始めると、抜け漏れが生じたり、思考が堂々巡りしたりしがちです。フレームワークを使うことで、**思考を構造化し、誰もが同じ視点から議論できる共通言語**を持つことができます。

---

## なぜフレームワークを使うのか

| 課題 | フレームワークで解決できること |
|------|-------------------------------|
| 何から考えればいいかわからない | 考える「切り口」を与えてくれる |
| 大事な観点を見落としてしまう | 網羅的に検討できる |
| チームで議論が噛み合わない | 共通の視点・言語を提供する |
| 結論が感覚的になってしまう | 論理的・定量的に判断できる |

---

## フレームワークの5つの活用シーン

本カリキュラムでは、以下の5軸＋リスク分析でフレームワークを体系的に学びます。

```
① 分析する   → 市場・競合・自社を客観的に把握する
② 整理する   → 情報・問題を構造化して整理する
③ 決める     → 優先順位を付け、意思決定を下す
④ 改善する   → 継続的に改善し、目標を管理する
⑤ 発想する   → 新しいアイデアを生み出す
⑥ リスクを見る → 失敗・脅威を事前に識別する
```

## フレームワークを使う上での心得

### 1. フレームワークは「手段」であって「目的」ではない

フレームワークに当てはめること自体がゴールになってしまうと本末転倒です。**使うべき場面・問いを先に明確にしてから**、適切なフレームワークを選びましょう。

### 2. 「型」を知った上で、状況に合わせてアレンジする

すべての状況に完璧に当てはまるフレームワークはありません。ベースの型を理解した上で、実際の問題に応じて柔軟に応用することが大切です。

### 3. 複数のフレームワークを組み合わせる

一つのフレームワークだけでは見えない視点が、別のフレームワークを使うと浮かび上がることがあります。例えば SWOT 分析の後に STP 分析を行うなど、組み合わせて使うのが実践的です。

### 4. アウトプットを出して終わりにしない

フレームワークを埋めること自体は分析の「入口」です。その後、**「So what?（だから何？）」と問い続け**、具体的なアクションに落とし込むことで初めて価値を生みます。

## フレームワーク選択の目安

| やりたいこと | 使うフレームワーク |
|---|---|
| 市場や業界を把握したい | 3C・PEST・5Forces |
| 自社の立ち位置を整理したい | SWOT・STP |
| 問題を漏れなく整理したい | MECE・ロジックツリー |
| 原因を深掘りしたい | なぜなぜ分析・仮説思考 |
| 優先順位を付けたい | Eisenhowerマトリクス・ICEスコア |
| 顧客を理解したい | カスタマージャーニー・JTBD |
| 改善サイクルを回したい | PDCA・OODAループ |
| 新しいアイデアを出したい | SCAMPER・ラテラルシンキング |
| リスクを洗い出したい | リスクマトリクス・FMEA |

---

> フレームワークは「頭の引き出し」です。引き出しが多いほど、どんな場面でも素早く整理・判断できるようになります。まずは一つひとつ丁寧に学び、実務の中で使ってみましょう。

## 練習問題

### 問題1：フレームワークの選択

以下の3つのシナリオに対して、このレッスンで紹介したフレームワーク選択の目安を参考に、**最も適切なフレームワークを1つ選び、その理由を1〜2文で述べてください。**

**シナリオA**
新しい食品宅配サービスを始めようとしている。競合が多いため、まず業界全体の収益構造と自社が勝てる領域を把握したい。

**シナリオB**
プロジェクトのタスクが溢れており、何を先に片付けるべきか判断できない状態にある。

**シナリオC**
営業チームの受注率が先月から急落している。どこに問題があるのか、まだ原因の仮説が絞り込めていない段階である。
