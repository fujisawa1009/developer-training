## 事業を「設計」する視点

事業やプロダクトを作るとき、「どんな価値を・誰に・どうやって届け・どう収益を得るか」を体系的に設計することが重要です。このレッスンでは、事業・プロダクト設計に使う4つのフレームワークを学びます。

---

## ビジネスモデルキャンバス（BMC）

**ビジネスモデルキャンバス**は、アレックス・オスターワルダーが考案した、事業の全体像を1枚のキャンバスで可視化するフレームワークです。

### 9つのブロック

```
┌────────────┬─────────────┬──────────────┬─────────────┬──────────────┐
│ KP         │ KA          │ VP           │ CR          │ CS           │
│ 主要パート  │ 主要活動     │              │ 顧客との     │ 顧客セグメント│
│ ナー       │             │ 価値提案      │ 関係性       │             │
├────────────┤             │              ├─────────────┤             │
│ KR         │             │              │ CH          │             │
│ 主要リソース│             │              │ チャネル     │             │
├────────────┴─────────────┴──────────────┴─────────────┴──────────────┤
│ C$：コスト構造                          │ R$：収益の流れ                │
└────────────────────────────────────────┴──────────────────────────────┘
```

### 9ブロックの説明

| ブロック | 内容 | 問い |
|---|---|---|
| **CS（顧客セグメント）** | どんな顧客を対象にするか | 誰のために価値を作るか |
| **VP（価値提案）** | 顧客にどんな価値を届けるか | 何を提供するか・どんな問題を解くか |
| **CH（チャネル）** | どのルートで届けるか | 直販・代理店・Web・店舗 |
| **CR（顧客関係）** | 顧客とどう関係を築くか | セルフサービス・専任担当・コミュニティ |
| **R$（収益の流れ）** | どこから収益を得るか | 単発・サブスク・広告・手数料 |
| **KR（主要リソース）** | 事業に必要なリソース | 人・技術・特許・ブランド |
| **KA（主要活動）** | 事業に必要な活動 | 開発・営業・物流・サポート |
| **KP（主要パートナー）** | 必要な提携先・外部リソース | サプライヤー・提携会社 |
| **C$（コスト構造）** | どんなコストがかかるか | 固定費・変動費・スケールでの変化 |

### 使い方のポイント

- CS（顧客）と VP（価値提案）の整合性が最重要
- 1時間でドラフトを作り、議論しながら修正する
- 事業の変化に合わせて定期的に見直す

## バリューチェーン

**バリューチェーン（価値連鎖）**は、マイケル・ポーターが提唱した、企業が顧客に価値を届けるまでの一連の活動を可視化するフレームワークです。どの活動が競争優位の源泉かを特定します。

### バリューチェーンの構造

```
主活動（顧客価値を直接生み出す活動）
┌─────────┬─────────┬─────────┬─────────┬──────────┐
│購買物流  │ 製造・  │ 出荷・  │マーケ・  │ アフター │→ マージン
│（調達）  │ オペレ  │ 物流    │ 販売    │ サービス │
└─────────┴─────────┴─────────┴─────────┴──────────┘
支援活動（主活動を支える活動）
┌───────────────────────────────────────────────────┐
│ 全般管理・人事・技術開発・調達インフラ              │
└───────────────────────────────────────────────────┘
```

### 活用のポイント

- 各活動に**コスト・強み・改善余地**を書き込む
- 競合との比較でどの活動に優位性があるか分析する
- アウトソースすべき活動（弱み・非コア）を特定する

## JTBD（Jobs To Be Done）

**JTBD**は、顧客が製品・サービスを「使うのは何のジョブ（仕事・目的）を達成するためか」という視点でニーズを理解するフレームワークです。

### JTBD の核心

> **顧客は製品を買うのではなく、「達成したいこと（ジョブ）」のために製品を「雇う」。**

### 有名な例

「クライアントはドリルを買うのではなく、**穴を開けたいから**ドリルを買う。さらに本当は**棚を取り付けたい**から穴を開ける。」

### ジョブの3層構造

| 層 | 内容 | 例（音楽サービス） |
|---|---|---|
| **機能的ジョブ** | 具体的なタスク | 音楽を聴く |
| **感情的ジョブ** | 感じたい感情 | 好きな音楽でテンションを上げたい |
| **社会的ジョブ** | 他者からどう見られたいか | 音楽のセンスが良いと思われたい |

### JTBD インタビューの問い

- 「このサービスを使い始めたきっかけは何でしたか？」
- 「使う前、どんな状況・感情でしたか？」
- 「このサービスで本当に達成したいことは何ですか？」

## PMF（プロダクトマーケットフィット）

**PMF（Product-Market Fit）**は、プロダクトが市場のニーズと深く合致した状態です。スタートアップ・新規事業において最重要の概念です。

### PMFの判断基準（ショーン・エリス指標）

> 「このサービスが使えなくなったらどう感じますか？」
> → **「非常に残念」と答える人が40%以上**であればPMFに近い

### PMFに至るまでのステップ

```
① Problem-Solution Fit（課題の特定）
   → 「本当に存在する課題に対するソリューションか？」

② MVP（最小限の製品）の投入
   → 「最小コストで検証できるプロダクトは何か？」

③ Product-Market Fit の検証
   → 「顧客がお金を払い・継続して・口コミで広めるか？」

④ スケール
   → 「PMF達成後に初めてグロース施策に投資する」
```

### PMF前にスケールしてはいけない理由

PMFが達成されていない段階でマーケティング・営業コストをかけても、顧客は定着せず、LTVが低いまま CAC だけが高くなる（= 事業が成立しない）。

---

## まとめ：事業設計フレームワークの連携

```
BMC     → 事業の全体構造を1枚で可視化する
バリューチェーン → どの活動に強みがあるかを分析する
JTBD    → 顧客が本当に求めているものを深掘りする
PMF     → プロダクトと市場の合致を確認する
```

> 事業設計は「いいプロダクトを作ること」ではなく「顧客のジョブを達成できるプロダクトを、持続可能なビジネスモデルで届けること」です。
