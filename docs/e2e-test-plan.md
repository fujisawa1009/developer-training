## 概要

ユニットテスト（228件）では検知できない「画面操作で壊れる」バグを検出するため、
Playwright による E2E テストで主要フローをカバーする。

### ユニットテストとの役割分担

| 観点 | ユニットテスト（Vitest） | E2Eテスト（Playwright） |
|------|----------------------|----------------------|
| Server Actions のロジック | **対象** | 間接的に検証 |
| コンポーネントのレンダリング | 対象外 | **対象** |
| 画面遷移・リダイレクト | モックで検証 | **実際のブラウザで検証** |
| Server/Client Component 境界 | 検知不可 | **検知可能** |
| フォーム送信→結果表示 | 個別に検証 | **E2Eで一気通貫検証** |

## Phase 0: テスト基盤セットアップ

### 0-1. パッケージ追加

```bash
docker compose exec app npm install -D @playwright/test
docker compose exec app npx playwright install --with-deps chromium
```

### 0-2. playwright.config.ts

`app/playwright.config.ts` を作成:

```typescript
import { defineConfig } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  timeout: 30_000,
  retries: 1,
  use: {
    baseURL: "http://localhost:3000",
    screenshot: "only-on-failure",
    trace: "on-first-retry",
  },
  projects: [
    { name: "chromium", use: { browserName: "chromium" } },
  ],
});
```

### 0-3. npm scripts 追加

`package.json` に追加:

```json
"test:e2e": "playwright test",
"test:e2e:ui": "playwright test --ui"
```

### 0-4. 認証ヘルパー

`app/e2e/helpers/auth.ts`:

- `loginAsAdmin(page)` — admin@example.com でログイン
- `loginAsInstructor(page)` — instructor@example.com でログイン
- `loginAsLearner(page)` — learner@example.com でログイン
- 各関数: ログインページへ遷移 → メール・パスワード入力 → 送信 → ダッシュボード表示を待機

### 0-5. テストデータ前提

E2E テストは seed データが投入済みの状態で実行する。

| ロール | メール | パスワード |
|--------|--------|-----------|
| admin | admin@example.com | password123 |
| instructor | instructor@example.com | password123 |
| learner | learner@example.com | password123 |

### 0-6. 実行方法

```bash
# コンテナ内で実行
docker compose exec app npm run test:e2e

# UI モード（ローカル開発時）
docker compose exec app npm run test:e2e:ui

# 特定ファイルのみ
docker compose exec app npx playwright test e2e/auth.spec.ts
```

## 注意事項

### テストデータの前提
- seed データが投入済みであること（`npx prisma db seed`）
- E2E テスト実行前にアプリケーションが起動していること（`http://localhost:3000`）

### テスト間の独立性
- 各テストファイルは独立して実行可能であること
- テスト #5（課題提出）は seed にカリキュラム＋課題データが必要
- テスト #8（採点）はテスト #5 で提出されたデータに依存 → テスト内で提出まで行う、または seed データに提出済みデータを含める
- テスト #6 で作成したユーザーは同テスト内で削除し、他テストに影響しないようにする

### コンソールエラーの監視
- 全テストで `page.on("pageerror")` を監視し、JavaScript エラーが発生した場合はテスト失敗とする
- 今回修正した「Event handlers cannot be passed to Client Component props」のようなエラーを検知できる

### CI/CD 対応
- GitHub Actions での実行を想定（Phase 4 の 4-6 で対応予定）
- Playwright の Docker イメージまたはコンテナ内実行で対応
